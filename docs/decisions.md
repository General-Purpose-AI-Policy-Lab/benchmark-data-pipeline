## 2026-09-04, second batch

- **A1 · Rename done.** GitHub repository renamed to `benchmark-data-pipeline` (redirect from the old name), local folder and remote updated. The uuid5 namespace string is changed to `benchmark-data-pipeline` in the same move: no consumer reads the ids yet, and the benchmark renames below change most `benchmark_id` values anyway.
- **A2 · Language.** English everywhere: code, docstrings, comments, README, docs.
- **A3 · Harness.** Recorded, but **not** part of the model identity. A model's score on a benchmark is its best score across harnesses / scaffolds; `scores.csv` carries the `harness` that produced the kept score. Sources: Epoch's `Harness` / `Scaffold` / `Agent` columns (`FILE_HARNESS_COLUMN`), and the harness token of Scale SEAL composite names (`Claude Opus 4.8 (Claude Code) max`), carried by a new `harness` column in every `aliases.csv`.
- **A4 · Country.** ISO 3166-1 alpha-2 in `organizations.csv` and `models.csv` (`US`, `CN`, `FR`, ...; several countries as `US,CN`). The US / CN / Other bucketing belongs to consumers.
- **A5 · Benchmark scope.** Exclusions are decided **in the data pipeline**, at ingestion, so that no release date has to be found for a model seen only on an excluded benchmark. One set of criteria for both analyses, one row per benchmark in `0_input/metadata/benchmarks.csv` with a `status` and the criterion that fails: (1) scores are a proportion in [0, 1]; (2) the benchmark measures a capability, not a propensity; (3) it was run on a good share of the frontier models of its evaluation period; (4) its quality is sufficient for the ranking of scores to be informative. Being old, saturated or no longer evaluated is **not** a reason to exclude; errors in the item set are tolerated (the forecasting model infers the upper asymptote; Multiaxis handles it separately). Applied: HiL-Bench (2); ANLI, ScienceQA, MindCube, SpatialViz-Bench (3); SWE-Bench verified, SWE-Bench Pro, SWE-Bench Pro (Private), CursorBench, LiveBench (4). MX's "easy for humans" list and MBF's "legacy" list are no longer exclusion reasons: ARC-AGI, ARC-AGI-2, HellaSwag, OpenBookQA, PIQA, SimpleBench, VPCT, Winogrande, BBH, BoolQ, LAMBADA, MMLU, SuperGLUE, TriviaQA, CSQA2, GPQA Main / MMLU Biology and Chemistry are included (VideoMME: see the third batch).
- **B1 · Names.** Epoch's name when Epoch publishes the benchmark (`benchmark` column of `benchmark_metadata.csv`), otherwise the authors' spelling. Version numbers are part of the name. 24 renames applied (`previous_names` column of `benchmarks.csv`).

- **B3 · Floors.** METR Time Horizons stays at 0.05, TriviaQA at 0.127, ScienceQA at 0.3983 and SuperGLUE at 0.443: the existing justifications are judged sound. Epoch publishes 0 for the first two and 0.25 / 0 for the last two; the difference is recorded in the `floor_reason` column.

## 2026-09-11, human baselines for METR Time Horizons

- **One row added** (user), recomputed from METR's released run data rather than quoted from a publication, a first for `human_baselines.csv`: `Committee of Domain Experts` 0.8301. Source: `reports/time-horizon-1-1/data/raw/runs.jsonl` in `github.com/METR/eval-analysis-public`, rows with `alias == "human"` (773 runs, 188 of the 228 tasks). Aggregation is the invsqrt task weighting, which reproduces Epoch's `average_score` to four decimals on each of the 20 agents the run table covers (GPT-5.3-Codex 0.7454 against 0.745439, Claude Opus 4.6 0.7886 against 0.788644, Gemini 3 Pro 0.7098 against 0.709822), so the figure sits on the ingested metric.
- **`Committee of Domain Experts` uses best-of-all-attempts, not a fixed best-of-k** (user decision, against the recommendation of a fixed best-of-3 at 0.80): attempts per task run from 1 to 69 and METR collected more of them where baselines failed, so the committee lift lands on the hard, densely baselined tasks while the sparsely baselined ones stay near their single-attempt value, which the user judged a reasonable compensation. Each attempt is a distinct person (HCAST assigns one baseliner per task; SWAA was baselined 3 to 4 times per task by METR employees; RE-Bench reuses the RE-Bench expert pool), so "committee" is literal. For reference: fixed best-of-2 0.770, best-of-3 0.803, best-of-5 0.825, and the parametric `1 - (1 - p)^3` 0.775.
- **No `Domain Expert` row** (user): the single-attempt mean, 0.6632 on the same weighting, is too biased to publish as a baseline. METR itself declines to use it, because many baseline failures come from reasons that do not apply to models (expertise mismatched with the task, giving up, a speed bonus that rewards abandoning hard tasks), and the HCAST paper warns it "is not directly comparable to the success rates of agents". It measures the baselining protocol as much as the humans, so only the committee figure goes in.
- **The comparison is asymmetric and the note says so.** `average_score` is a mean over runs while the row is a best-of-N, and under the same best-of-N rule the models rise too: on the 188 baselined tasks Claude Opus 4.6 goes from 0.825 to 0.886 and GPT-5.2 from 0.781 to 0.824. Read without its note, the 0.8301 row suggests humans still lead, which is false.
- **Remote Labor Index gets no row.** Its human baseline is the freelance deliverable itself, kept only when "a reasonable client would accept it" (cleaning criterion 3 of the paper), and the automation rate is defined as the probability of a win or tie against it, which is why its Elo is fixed at 1,000 rather than measured. There is no second human deliverable per project and no human-vs-human comparison anywhere in the release, so the only honest value is 1.0 by construction. Left out; revisit if a version ships a second deliverable.
